# B 方案：右侧三点与按键反馈灯窗

2026-10-09。苹果冷灰配色与灯珠、玻璃绘制参数见 [实现说明](pis-apple-glass-implementation.md)。下文保留对应阶段的实现记录。

开发版 `pis-v2-feedback-neutral-bright` 已编译并安装到 x86_64 模拟器。验证范围为构建与安装，真机和完整功能测试待完成。

## 最终选择

使用 Kotlin + 现有 InputMethodService + 自定义 View/Canvas + 单个 ValueAnimator + 显式事件状态。

这是此前原生 Canvas 方案的具体落地方式。ValueAnimator 统一驱动亮度和位置插值，不再另外建立 Choreographer 帧循环；不引入图片帧、Lottie、WebView 或新的界面框架。

## 布局

- 顶部栏仍为 56dp。右侧反馈模块固定 68dp，里面是三个圆点和 2 行 × 12 列的 24 颗灯珠。
- 左侧候选栏、完整译文栏、语音栏均约束到反馈模块左边，动画不改变文字区的宽度、字号或位置。
- 原候选下拉箭头和闲置收起按钮已移除。点击右侧 68dp 点阵区域：正在组词时展开候选，再点收回；没有正在输入的拼音时收起键盘。候选文字获得原箭头占用的空间。
- 红、黄、绿三点仍显示状态；右侧整块模块是统一触摸区域，不设三个独立按钮。
- 按最新样图统一为灰白配色：红 #E8472D、黄 #EBB81A、绿 #37BA31 三灯；浅灰灯窗、灰色未亮点、暖白 #FFF7EC 亮点及轻暖光晕。所有动作沿用运动与亮度区别，颜色状态由三灯提示。
- 原来横贯顶部的点阵背景、旧 matrix 开关和随机动画不恢复。

## 已接事件

| 动作 | 灯窗反馈 |
| --- | --- |
| 字母、数字 | 键盘横向位置映射到 12 列，所在行映射到两行；暖白亮点移到对应位置 |
| 连续输入 | 最多保留 3 个旧位置作短拖尾；新按键从当前画面接续，不排队 |
| 删除 | 暖白亮点从右向左回退；连续删除沿当前轨迹继续，不每次跳回最右侧 |
| 空格 | 暖白从中央向两端展开 |
| 回车 | 双向汇聚、短暂全亮；只表示动作反馈，不表示消息发送成功 |
| Shift | 下排向上排跃迁，暖白；长按锁定额外保留低亮下排标记 |
| 中英切换 | 实际收到引擎 IMChange 后左右两组交换；暖白标记停在当前语言一侧 |
| 数字/文字布局切换 | 两组暖白亮点交换 |
| 标点、剪贴板入口 | 相邻两点交替跳动，暖白 |
| 点击候选、释义显示 | 三点柔绿扩散收束；候选点击反馈只代表操作被接收 |
| 翻译 | 请求开始后暖白往返等待；结果返回柔绿；失败由红灯提示；取消立即清理 |
| 语音准备 | 暖白往返等待 |
| 麦克风已启动 | AudioRecord 确认开始录音后进入聆听状态；使用真实采样 RMS 控制灯珠亮度及范围 |
| 语音处理中 | 松手和标点处理阶段进入暖白等待；候选就绪由绿灯提示；确认写入按 commitText 返回值显示结果 |

普通按键约 180ms，空格/切换约 240ms，回车约 280ms，任务等待周期 1100ms。结束后保留低亮标记，约 2.2 秒无新事件后，用 160ms 淡回待机。待机与停留图案没有持续帧回调。

灯窗在翻译请求期间显示等待状态，结果和失败分别通过状态灯反馈。

## 源码与事件边界

- `app/src/main/java/org/fcitx/fcitx5/android/pis/feedback/PisFeedbackEvent.kt`：类型化事件、键位映射、任务种类、任务 token、阶段和音量。
- `app/src/main/java/org/fcitx/fcitx5/android/pis/feedback/PisFeedbackView.kt`：24 点及三灯绘制、主题配色、当前帧快照、拖尾、单个可取消的 ValueAnimator。
- `InputView.kt`：固定布局和实际语言变更事件。
- `FcitxInputMethodService.kt`：转发事件，字段切换及键盘结束输入时 reset。
- `CommonKeyActionListener.kt`、`KeyboardWindow.kt`：普通按键及布局动作。
- 候选组件、`BaseInputView.kt`：候选点击及本地词义展示反馈。
- `PisTranslationCoordinator.kt`：翻译请求、结果、取消和应用译文。
- `PisVoiceCoordinator.kt`、`PisVoiceEngine.kt`：语音生命周期，以及录音开始和音量采样回调。

反馈视图不读取 InputConnection，不提交文字，不保存用户文本或音频。只有业务协调器决定是否开始任务、完成任务和写入文本。

录音/翻译的准备、聆听、处理状态优先于普通按键；取消事件必须匹配任务种类及 token，旧完成事件不能覆盖另一个任务。已有业务层的连接/快照/代次检查仍保留。

## 生命周期与减少动画

- 一次按键替换当前动画，复用 24 个点的数组和画笔，不创建独立按键动画队列。
- 任务等待仅在键盘可见且任务未完成时循环；结束、取消、字段切换、隐藏及视图移除会停止时钟。
- 隐藏/未附着视图忽略迟到反馈，不能被后台结果重新启动动画。
- 系统动画关闭或应用禁用动画时，只更新静态状态/音量亮度，不播放移动、拖尾或循环动画。
- 颜色和宽度随输入视图的主题重建生效；按键布局、原字号、双拼提示及声音震动设置保持现有实现。

## 灰白配色与双语查询补充

最新默认浅灰主题：键盘底 #DEDEDE，顶部 #EBEBEB，字母键 #F3F3F3，功能键 #CECECE，主字 #171C1F，短释义提示 #7C7C7C；双拼声母/韵母小标统一灰色，整条顶部栏使用相同 #EBEBEB 背景。旧默认浅灰自动迁移；自定义/深色等主题仍可选择。

输入法服务启动后的第一次输入默认激活中文（全拼或当前首道双拼），本次服务运行中手动切英文后，切换输入框不会反复强制改回中文。

长按弹窗通过 `PisGlossary.lookupLegacy` 读取 `gloss.db` 的 zh/llm/en 表。英文显示中文释义、音标与词性，中文显示英文译义。缺词显示未收录，查询缓存与其他数据源隔离。候选提示使用独立查询路径。

此阶段 assembleDebug 通过（41 秒），已安装到模拟器。验证范围为构建与安装。
## 圆角输出栏与键帽质感

输出栏改为单一 FrameLayout 圆角容器，统一主题 barColor，12dp 圆弧并开启 clipToOutline。候选、译文、语音及点阵均在这个容器内，右侧灯窗仍固定 68dp，整栏仍高 56dp。切换显示内容不会出现不同底色的方角接缝。

新增 PisKeycapDrawable，替换普通有边框键的平面阴影背景：上亮下暗的三段原生渐变、细边缘高光、柔和底部阴影；按下时表面下沉 0.75dp、阴影收短、亮度略降低。字母、功能键、空格与纯数字键复用同一材质，根据主题原底色计算，深色/自定义色仍可使用。旧背景内容 padding 保留，字母字号、统一基线、布局及触摸区域保持。无图片纹理或新帧循环；渐变仅在尺寸及按压状态变化时重建。

此阶段已完成构建与模拟器安装，输入和观感测试待完成。
## 长按词库查询

长按词义查询使用 `app/src/main/assets/pis-input/gloss.db`，表数量为 zh 109913、llm 148195、en 59248。音标与词性来自 en 表，整句翻译独立通过长按句号触发。
## 去除键盘下半部暖黄

默认浅灰调色板的背景、键帽、功能键、阴影均改成 R=G=B 的中性灰；分别为 #DEDEDE / #F3F3F3 / #CECECE / #B5B5B5，顶部 #EBEBEB。渐变由这些中性底色与纯黑/纯白混合，不再带暖黄；双拼小标和释义提示也使用中性灰。此前默认和暖灰主题按 palette_revision=3 自动迁移，用户自定义及其他主题不覆盖。红黄绿状态灯、暖白 LED 仍保留。

本版包含最新词库长按弹窗，开发版本名 pis-v2-feedback-neutral-bright；继续仅同步模拟器，不更新 ARM64 手机交付包。
## 灯珠亮度微调

亮点渲染强度为 min(1, sqrt(level) × 1.2)，提高待机和动画中低亮帧的可见度；峰值不超出暖白色上限。光晕 alpha 系数由 65 改为 90，半径由 2.5dp 改为 2.8dp。灰色未亮点、三灯配色、动画轨迹和计时不变；暖光仅在右侧模块内。

开发版 pis-v2-feedback-neutral-bright 包含此前中性灰去黄、词库长按、默认中文、统一圆角输出栏与键帽材质。
